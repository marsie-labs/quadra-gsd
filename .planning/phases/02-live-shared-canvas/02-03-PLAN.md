## Phase Goal

> ROADMAP Phase 2 Goal (verbatim): "Participants add cards to any quadrant, and every connected browser on the session sees them appear live, relayed by the Python server from Supabase Realtime."

Quoted verbatim; no user story is invented (see 02-01).

After this plan, every kind of card change made anywhere reaches every open canvas live. That covers edits, moves, soft and hard deletes, and changes typed into the Supabase SQL editor (SYNC-03). The canvas stays consistent when events are stale, duplicated, malformed or meant for another session. Live integration tests prove two clients converge and measure the ~1 s latency (SYNC-01, QUAL-02).

Phase 3 builds the edit/delete/move UI controls on top. This plan only makes the canvas render the current row state the database reports.

## Flagged assumptions

- **SYNC-03 (edge probe: unclassified, left unresolved):** covered by the outside-writer truths and the end-of-phase SQL-editor human check, not by an edge row.
- **Outside writer stands in for the SQL editor in automation:** the hosted DB password is not available to the test suite, so a separate PostgREST client that never touches the app's code path plays the "outside the app" writer. The literal SQL-editor run is an end-of-phase human check.
- **Latency threshold:** Phase 1 measured probe round trips of 0.36-1.27 s on this hosted project. A median of 1.5 s or less over 5 samples is the automated reading of "within ~1s". Each sample is hard-capped at 5 s.

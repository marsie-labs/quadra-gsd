## Phase Goal

> ROADMAP Phase 2 Goal (verbatim): "Participants add cards to any quadrant, and every connected browser on the session sees them appear live, relayed by the Python server from Supabase Realtime."

Quoted verbatim; no user story is invented (see 02-01).

This plan hardens the authoring half of the slice that 02-01 proved. After it lands:
- **Task 1:** the database refuses blank authors from any writer, and the stored card shape (CARD-07) is proven live.
- **Task 2:** participants get clear messages for empty or oversized text, and cards render literally.
- **Task 3:** an unnamed participant is asked for a name at the moment of adding, double submits create one card, and failures keep the typed text.

## Carried-forward decisions and findings

- **Phase 1 D-02** (locked): every card has a real author; the add path calls `ensure_display_name()` and aborts on None. 02-01 wired the call; Task 3 proves its edge cases.
- **Phase 1 D-03 / D-04** (locked): the name is fixed per browser once set, 1-40 code points after trimming, and duplicates are allowed.
- **Phase 1 review WR-07 / security R4** (assigned to "Phase 2 (IDEN-03)"): `cards.author` and `workspaces.closed_by` CHECKs accept space-only values. Task 1 adds the forward migration. The pushed init migration is never edited.
- **Phase 1 review WR-06:** the banner and dialog handlers can delete an already-deleted element. Task 3 fixes it, because adding a card now runs through `ensure_display_name()`.

## Flagged assumptions

- **Postgres `btrim` strips only U+0020 spaces**, while Python `str.strip()` strips all Unicode whitespace. The app rule is therefore the stricter one for UI writes. The database rejects space-only values from any writer, but a tab-only author written directly in SQL would still pass the DB. This is accepted: the Python gate is the authoring path, and the DB constraint is defense in depth (WR-07 scope).
- **IDEN-03 concurrency (edge probe, backstop):** two tabs of one browser naming at the same time cannot be simulated by the NiceGUI user fixture, because each simulated user is a separate browser. It is recorded as a backstop truth; `save_display_name` returning the stored name is already unit-tested in Phase 1.

## Phase Goal

> ROADMAP Phase 2 Goal (verbatim): "Participants add cards to any quadrant, and every connected browser on the session sees them appear live, relayed by the Python server from Supabase Realtime."

Quoted verbatim; no user story is invented (see 02-01).

Realtime does not replay missed events (PITFALLS.md Pitfall 3). After this plan, a participant whose browser dropped off, or who reopens after the server restarted, sees the current canvas with nothing missing. A transient database failure no longer tells them their valid link is unknown (ROADMAP success criterion 4, SYNC-04).

How browsers come back, and what covers each case:
- **Short socket drop** (shorter than NiceGUI's 3 s `reconnect_timeout`): the server-side client survives. NiceGUI retransmits buffered UI messages, and this plan additionally resyncs from the database on the reconnect handshake.
- **Longer drop or server restart:** the server-side client is gone, NiceGUI reloads the page, and the page reads the database again.

Plan 02-05 covers the server side: the hub's own Realtime connection dropping and recovering.

## Flagged assumptions

- **SYNC-04 (edge probe: unclassified, left unresolved):** covered by the truths above and the end-of-phase reconnect/restart human check.
- **Reconnect simulation:** the NiceGUI user fixture has no real socket. Tests replay a reconnect by invoking the page client's `connect_handlers`, which is the same list `Client.handle_handshake` runs on every socket handshake (verified in nicegui 3.18 client.py). A real browser reconnect is an end-of-phase human check.

NiceGUI 3.18 facts this plan relies on (verified in .venv nicegui/client.py):
- `Client.handle_handshake` calls every `client.connect_handlers` entry on EACH socket handshake (first connect and every reconnect).

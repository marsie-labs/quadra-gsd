Library facts verified in 01-RESEARCH.md (realtime 2.33):
- `AsyncRealtimeClient(url, token=key)`: an https URL becomes wss, and the key goes into the `?apikey=` query. Never log the client URL.
- `channel.on_postgres_changes(event, callback, table=None, schema=None, filter=None)`: callback is the 2nd positional parameter. All bindings must be added before the single `subscribe()`.
- `channel.subscribe(callback(state, err))` reports `RealtimeSubscribeStates.SUBSCRIBED | TIMED_OUT | CLOSED | CHANNEL_ERROR`.
- Postgres-changes callbacks are called synchronously inside the socket listen loop, so they must be plain `def`.
- The callback payload is a plain dict: `payload["data"]["type"]` ("INSERT"/"UPDATE"), `payload["data"]["record"]`, `payload["data"]["table"]`.
- `AsyncRealtimeClient.connect()` retries 5x with backoff, then raises; `close()` disconnects.

   - **`class RealtimeHub`** with `__init__(self, supabase_url: str, key: str)`:
     - creates `AsyncRealtimeClient(f"{supabase_url.rstrip('/')}/realtime/v1", token=key)`;
     - keeps the key only for sanitizing;

   - `_on_probe(self, payload)` is a plain def (Pattern 4). It reads `payload["data"]["record"]["nonce"]` defensively and resolves the matching not-done waiter with `time.monotonic()`.
   - `_register_waiter(nonce)` returns a new future stored under that nonce.
   - **`async start(timeout=15.0)`:**
     - await `self._rt.connect()`; any exception becomes `RealtimeCheckError("connect", sanitized str)`;
     - build the channel; await `subscribe(on_state)`, where the state callback resolves a future on SUBSCRIBED and fails it on TIMED_OUT, CLOSED or CHANNEL_ERROR (including the server/client bindings-mismatch error);

   - **`async verify_roundtrip(write_probe, timeout=15.0, resend_every=3.0) -> float`:**
     - nonce = `secrets.token_hex(8)`;
     - loop: `await write_probe(nonce)`, where an exception becomes `RealtimeCheckError("probe-write", sanitized)`; then wait on the shielded waiter for resend_every; re-upsert until the waiter resolves or `timeout` elapses (then raise `RealtimeCheckError("no-event", f"no realtime_probe change event arrived within {timeout:.0f}s")`);
     - always pop the waiter;
     - return the elapsed ms.
     - This bounded re-write is part of the one-time startup proof: at most timeout/resend_every probe writes, only during startup. It is not data polling. It never reads rows back; success comes only from the Realtime event, and after startup the server learns about changes only from Realtime events (CLAUDE.md no-polling rule).

     - on success: state "verified", record latency_ms, INFO log "Realtime startup check verified: DB change event received in %.0f ms". Only this path may set "verified"; reaching SUBSCRIBED alone never does;
     - on RealtimeCheckError: state "failed", record stage and sanitized error, then re-raise for "strict" or log at ERROR level for "warn".

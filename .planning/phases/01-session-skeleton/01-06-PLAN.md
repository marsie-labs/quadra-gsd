## Phase Goal

> ROADMAP Phase 1 Goal (verbatim): "A user can create a session, share its unguessable link, and teammates can open it, enter a display name, and see the four labeled quadrants. The schema, project setup and Realtime connection are proven underneath."

This expansion slice adds the participant identity on top of the tracer's canvas, exactly as locked in CONTEXT.md:
- **D-01:** inline banner, not a modal and not a join screen;
- **D-02:** a reusable `ensure_display_name()` gate, with no placeholder author;
- **D-03:** the name is fixed per browser and shown read-only in the header;
- **D-04:** names are trimmed, 1-40 characters, and duplicates are allowed.

**Requirement remapping (revision 2, user decision 2026-10-22):** IDEN-03 (display name recorded as card author) moved to Phase 2, where CARD-01 first creates cards. This plan no longer claims IDEN-03. Nothing is dropped: the `cards.author` CHECK (01-02 migration), `validate_display_name`, the `ensure_display_name()` gate and the DB author-constraint test all stay, re-framed as D-02 groundwork that Phase 2's IDEN-03 builds on. The former IDEN-03 edge rows and prohibition are re-filed below under IDEN-01 / IDEN-02.

It also owns the fast two-browser SESS-04 test (`tests/ui/test_canvas.py`). That test moved here from 01-03 in revision 1 so 01-03 stays under the per-plan file budget. It belongs with the other second-browser checks in this plan, and it now also guards the canvas against this plan's header and banner edits.

This plan adds the last slice and closes the phase:

- **Task 2:** proves reordering live against hosted Supabase: propagation, reload, one-row writes, concurrent convergence and a same-card race. It also documents every card action in the README.

## Carried-forward decisions

- **D-07:** menu order Edit, Move to, Move up, Move down, Delete. This plan inserts Move up and Move down.
- **D-10 (locked):** Move up and Move down are shown but disabled on the first and last card, and both are disabled on a single card.
- **CLAUDE.md / Pitfall 8:** gapped double-precision ordering; never renumber a quadrant.

## Design decisions recorded here (Claude's discretion: reorder mechanics and concurrency)

- **Pure `reorder_index(ordered, card_id, direction)`** works on the quadrant's live cards in display order as (id, order_index) pairs. For "up" with neighbour P just before the card:
  - hi is P's order_index;
  - lo is the order_index of the nearest earlier card whose value is strictly below hi;
  - the result is the midpoint (lo + hi) / 2, or hi - 1024 when there is no such card.

  "Down" mirrors it. The result is None when the card is first or last, is absent, or no double lies strictly between lo and hi. Skipping cards tied with P guarantees the card really passes P, because ties sort by created_at and id.
- **The service decides from the database.** `reorder_card` reads the card (`get_card`) and its quadrant's order (`list_quadrant_order`), computes with `reorder_index` and writes once. When the result is None, it returns the card unchanged without writing. The UI uses the same function on what it shows for the optimistic position, so both agree whenever the screen is current.
- **Concurrency:** two reorders in one quadrant each compute from their own read and each write one row. The result can differ from what either participant intended, but every client projects the same rows with the same sort key (order_index, created_at, id), so screens and reloads always agree (SC-4). This is the last-write-wins model accepted for v1 (REQUIREMENTS Out of Scope: no CRDT).

## Flagged assumptions

- **CARD-05 (edge probe: unclassified, left unresolved):** the probe could not classify this requirement into an edge category. Its behavior is covered by the reorder truths above (edges, ties, one-row writes, convergence, rollback), not by an edge row.
- **Precision exhaustion is a silent no-op, by decision.** Repeatedly inserting into one gap exhausts it only after about 50 halvings, which a 2-10 person workshop will not reach. CONTEXT.md forbids renumbering, so when no double fits, the reorder does nothing rather than rewriting the quadrant.
- **Same-card race (backstop truth):** the live test fires two updates of one card concurrently, but cannot force them to overlap in the database. It proves the outcome either way, and the truth stays a backstop.

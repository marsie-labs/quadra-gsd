## Phase Goal

> ROADMAP Phase 3 Goal (verbatim): "Participants can edit, delete, move and reorder cards collaboratively, and their own actions feel instant."

Quoted verbatim; no user story is invented (see 03-01).

This plan completes the edit slice that 03-01 proved. After it lands:
- **Task 1:** editing behaves like a sticky note. It opens from the card's menu or a click on the text, Enter or a click away saves, Esc cancels, and Shift+Enter adds a line. Unchanged text writes nothing, invalid text keeps the editor open, and double submits write once. Anyone can edit without a name.
- **Task 2:** collaborative edits never destroy a draft (D-04). A remote change, a resync or a remote move keeps the editor open; a remote delete closes it with a warning; last save wins on every screen.

## Carried-forward decisions

- **D-01..D-05 (locked):** inline textarea; menu Edit and click-to-edit; Enter / Shift+Enter / blur / Esc; keep the local draft and last save wins; anyone can edit with no name.
- **D-07 (locked):** one menu button per card. This plan creates it with its first item, Edit. 03-03 adds Move to and Delete, and 03-04 adds Move up and Move down, keeping the order Edit, Move to, Move up, Move down, Delete.
- **03-01 projection model:** `_cards` holds server rows (stale guard), `_optimistic` the in-flight change, and `_render` updates the card element in place. This plan relies on `_render` never rebuilding a card.

## Design decisions recorded here (Claude's discretion)

- **Mid-edit remote move:** the card moves to its new quadrant with the editor open and the draft kept. Closing the editor would throw away typed text, which D-04's intent forbids.
- **Mid-edit remote delete:** the editor closes and the canvas warns "This card was deleted." There is nothing left to save the draft into.
- **"Unchanged" means unchanged against the text the editor opened with, or against the latest server text.** Opening and closing an editor without typing therefore never reverts someone else's change (D-03 and D-04 together).

## Flagged assumptions

- **Browser key handling cannot run in the NiceGUI user fixture.** The Vue `exact` modifier that lets Shift+Enter fall through, real focus loss on click-away, autofocus and touch opening of the menu run only in a real browser. Offline tests prove the registered listener types and the handlers; the browser behavior is an end-of-phase human check.
- **A browser may fire blur when a focused textarea is re-mounted** (for example after a remote move). That save is the user's own draft (D-03: blur saves) and is accepted.

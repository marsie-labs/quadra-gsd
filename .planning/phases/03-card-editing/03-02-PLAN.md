## Phase Goal

> ROADMAP Phase 3 Goal (verbatim): "Participants can edit, delete, move and reorder cards collaboratively, and their own actions feel instant."

Quoted verbatim; no user story is invented (see 03-01).

This plan hardens the edit slice that the 03-01 tracer proved:
- **Task 1:** rejected and failed edits roll back, a card deleted meanwhile is dropped with a warning, and the participant's own change is never duplicated or rebuilt when its confirmation and echo arrive. The fake repository learns card updates, mirroring the trigger, so every later plan can test writes offline.
- **Task 2:** the trigger's timestamp rules and edit_card's session scoping hold against hosted Supabase.

## Why this is its own plan

These proofs were first planned as 03-01's second task. Together with the tracer that projected about 120k tokens, above the 100k smart-zone budget (`workflow.smart_zone_tokens`), so they moved here unchanged in scope. 03-01 keeps the tracer and the README migration row.

## Carried-forward decisions

- **D-01 (locked):** edit validation reuses `validate_card_text` and `CARD_TEXT_ERROR`.
- **D-05 (locked):** the author never changes; edit_card has no author parameter.
- **D-06 (locked):** "(edited)" only after the text changed, carried by the card row (`text_updated_at`).
- **03-01 decisions:** cards_touch owns `updated_at` and `text_updated_at`; the projection keeps server rows in `_cards` and the in-flight change in `_optimistic`, and `_write` is the one guarded write path.
